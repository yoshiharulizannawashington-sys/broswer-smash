# Animation library, clip packs and the free asset workflow

This project now animates through a real `AnimationMixer` clip pipeline. This document covers what
ships, what is honestly still missing, and the exact steps to install licensed clip packs and the
Goku / Iron Man source models on a Chromebook.

## What ships in the repository

| Piece | File | Notes |
| --- | --- | --- |
| Rig adapter | `public/js/anim/rig_map.js` | Binds one canonical skeleton onto the prefab joint rig *or* an imported Mixamo/Blender bone rig. Handles `mixamorig:LeftUpLeg`, `upper_arm.L`, `Hips`, `Spine2`, etc. |
| Clip library | `public/js/anim/clip_library.js` | 39 authored clips (429 tracks, 1848 keyframes) in canonical bone space. |
| State machine | `public/js/anim/animation_controller.js` | One mixer per fighter, crossfades, priorities, one-shot locks, attack-window retiming. |
| Pack loader | `public/js/anim/animation_loader.js` | Loads installed GLB packs, retargets their clips, strips root motion, reports what matched. |
| Manifest | `public/data/animation-manifest.json` | The 39 clip ids, the candidate packs, their sources and licences. |
| Validator | `scripts/validate-animations.mjs` | `npm run validate:animations`. |
| Pack inspector | `scripts/inspect-animation-pack.mjs` | Reads any GLB's clips/bones and installs it as a pack. |

### The 39 clips

Movement: `idle`, `walk`, `run`, `sprint`, `turn`, `stop`, `strafe_left`, `strafe_right`.
Air: `jump`, `double_jump`, `fall`, `land`, `fly_start`, `fly_loop`, `fly_boost`, `fly_turn`, `fly_land`.
Combat: `fighting_idle`, `jab`, `cross_punch`, `heavy_punch`, `uppercut`, `front_kick`,
`spinning_kick`, `combo_1`, `combo_2`, `special_attack`.
Defence / reactions: `block`, `dodge_left`, `dodge_right`, `grab`, `throw`, `hit_light`,
`hit_heavy`, `launch`, `aerial_recovery`, `knockdown`, `get_up`, `knockout`.

**These 39 clips are hand-authored keyframe poses generated by this project. They are not motion
capture, and they are not Mixamo or Sketchfab content.** Downloaded packs replace them one clip id
at a time; anything a pack does not supply keeps using the authored clip.

### How combat stays authoritative

Gameplay keeps ownership of attack startup, active frames, recovery, hitboxes, damage and
knockback in `fighter3D.js`. The animation layer only *reads* that state:

1. `fighter.attackQueue` holds `{ kind, total, start, end }`.
2. The controller picks a clip for `kind` + `comboStep` (e.g. `heavy` → `heavy_punch`).
3. The clip is retimed so its strike peak lands on `(start + end) / 2` of the attack.
4. Damage still comes from the gameplay hitbox, never from the animation.

`npm run validate:animations` asserts step 3 numerically for five moves (drift ≤ 1 frame at 60 fps)
and asserts limb directions in world space, so an inverted rotation fails the build instead of
shipping.

## What is NOT in the repository, and why

- **The user-supplied Goku FBX and Iron Man glTF are still absent.** `public/models/characters/manifest.json`
  keeps both entries `enabled: false` until the files are installed. I cannot download copyrighted
  game/film characters, and no pipeline change makes that legitimate.
- **No clip packs are installed.** Sketchfab and Mixamo both require a signed-in browser session,
  a licence acceptance click and (for Sketchfab) author-enabled downloads. An agent in a headless
  VM cannot do that for you, and scraping protected assets is out of bounds.
- The shipped prefab characters are **not skinned meshes**: `character_models.glb` has 2434 meshes,
  0 skins and 0 animations. Articulation comes from 11 rigid joint nodes per fighter, which the clip
  library drives. It can never look like the sculpted hero models in a AAA fighter; only a real
  skinned character GLB will.

## Installing a clip pack (Chromebook-friendly)

Every step below happens in the browser. No local Blender or GPU software is needed.

### 1. Mixamo (best coverage, free)

1. Open <https://www.mixamo.com> and sign in with a free Adobe account.
2. Pick any humanoid character (the animations matter, not the mesh), then the **Animations** tab.
3. Search and download these, one at a time. Use **Format: glTF Binary (.glb)**, **Skin: Without Skin**,
   **Frames per second: 30**, **Keyframe Reduction: none**:
   - `Idle`, `Walking`, `Running`, `Sprint`, `Left Strafe Walking`, `Right Strafe Walking`
   - `Jump`, `Falling Idle`, `Landing`, `Flying`, `Flying Idle`
   - `Punching`, `Cross Punch`, `Hook`, `Uppercut`, `Front Kick`, `Spinning Kick`
   - `Blocking`, `Dodge`, `Grabbing`, `Throw`, `Hit Reaction`, `Stagger`, `Knock Down`,
     `Getting Up`, `Dying`
4. Combine them into one GLB. The easiest browser-only route is to open
   <https://gltf-viewer.donmccurdy.com>, drag the first GLB in, then use **Export** after appending
   clips in <https://gltf-transform.dev> or simply upload each file and let the loader use them:
   the manifest supports several packs, so `mixamo-locomotion.glb`, `mixamo-combat.glb` and
   `mixamo-reactions.glb` can each be their own pack entry.
5. Upload the `.glb` into `public/models/animations/` through the GitHub web UI
   (Add file → Upload files), or drop it there locally.

Mixamo licence: free for personal and commercial use, retargeting allowed. Re-check Adobe's
current terms before publishing.

### 3. Inspect before installing

```sh
node scripts/inspect-animation-pack.mjs ~/Downloads/Punching.glb
```

It prints meshes, skins, recognised bones, every clip with its duration, and which library ids the
clips can satisfy. If it reports `animations 0`, that download contains a mesh but no animation —
Sketchfab previews often do.

### 4. Install and enable

```sh
node scripts/inspect-animation-pack.mjs ~/Downloads/Punching.glb \
  --pack sketchfab-combat-combo --install
```

That copies the file to `public/models/animations/<pack-id>.glb`, fills in the clip mapping from
the manifest's name hints and flips the pack to `enabled: true, status: "installed"`. Add or edit
pack entries in `public/data/animation-manifest.json` to change the mapping by hand.

### 5. Verify

```sh
npm run validate:animations   # library, timing, limb directions, manifest integrity
npm run dev                   # then open http://localhost:3000
```

In the browser console:

```js
window.__browserSmashAssets.animationPacks   // per-pack loaded / missing / mapped counts
fighters[0].animationController.describe()   // active clip, external clips, rig, transitions
```

`externalClips` lists exactly which ids came from a downloaded pack. If it is empty, the packs did
not supply anything and the authored library is what you are watching — the UI will not pretend
otherwise.

## Goku and Iron Man models

The import path already exists and is manifest-driven. To install the real characters:

1. Put `Goku.fbx` plus its textures in `public/models/characters/goku/`.
2. Put `Iron Man Mark V Rig Materials.gltf`, its `.bin` and textures in
   `public/models/characters/iron-man-mark-v-rig/`.
3. Run `node scripts/install-character-assets.mjs <extracted-package>` (it validates the required
   files and flips `enabled` in `public/models/characters/manifest.json`).
4. `npm run validate:assets && npm run audit:roster` — the audit mounts every fighter and fails if
   the model or its weapon does not load.
5. `npm run dev`, pick Goku vs Iron Man, and check `fighters[0].characterModelLoaded` and
   `window.__browserSmashAssets.characterModels`.

Rigged GLBs loaded through that path keep their own baked clips (`model.userData.humanMixer`) and
are skipped by the clip controller so the two systems never fight over the skeleton. If such a
model arrives *without* clips, the loader can bind the clip library to its bones instead
(`resolveRig` falls back to bone-name classification).

## Known limitations

- **No root motion.** Downloaded clips have their translation tracks stripped on purpose: gameplay
  physics owns position, so a Mixamo walk cannot drag the fighter through the level. Foot sliding
  is the visible trade-off.
- **Retargeting is name+axis based.** A rig whose bone names are unrelated to humanoid conventions
  will map fewer bones; the inspector and `describe().missingBones` report that rather than hiding it.
- **The prefab rig has 11 joints.** No fingers, no spine chain, no separate hands, so clip detail
  is limited to gross body poses.
- **30 fps authoring.** Clips are sampled by the mixer at render rate; there is no motion warping.
