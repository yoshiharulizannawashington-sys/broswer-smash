# Character body audit — the real rigged models, what is on screen, and what is blocked

Written 2026-10-27 against the working tree (`work/gameplay-and-polish`, uncommitted), from files
that were inspected, loaded and measured — not from intent.

This is the Phase 5 report: **which fighters render a genuine skinned, animated 3D model, which
render a code-authored body, which still use the shared primitive prefab, and why the three
flagship Blender exports are built, verified and deliberately not enabled.**

## 3. Why the three flagship exports are not enabled

They were built (`assets/blender/build_roster_models.py`), verified, integrated, and then judged
from rendered frames against the authored bodies. The exports are **worse on screen**, so the
manifest entries are `enabled: false` and the authored body stays up. Evidence, both shots from the
same camera in the same session (`bash scripts/run-browser-test.sh scripts/_compare-bodies.mjs`):

| | Authored body | Blender export |
| --- | --- | --- |
| Goku | orange gi over a blue undershirt, lapels, sash, boots, gi cuffs, black spiked hair, face with eyes/brows/nose/mouth | an all-over orange body with pale patches across the chest and arms, two ball shoulders, two ball knees, no readable gi silhouette |
| Triangles | 33,222 | 6,128 |

Rendered frames are in `artifacts/body-compare/` (`goku--sculpted.png`, `goku--imported.png` and the
same pair for Iron Man and Iron Spider) and in `artifacts/phase5/`.

The defects, specifically:

1. **Coincident shells.** The exported body is one joined mesh of overlapping lofts: the near-white
   `fighter-undershirt` torso shell and the orange `fighter-gi` shell sit within a millimetre of
   each other over most of the chest, so they z-fight into a dithered orange/white patch. Turning
   shadow-receiving off did not change it (tested), so it is geometry, not shadow acne.
2. **Ball joints.** Shoulder and knee seams are covered by spheres (`0.070 m` shoulder,
   `0.052 m` knee) that read as balls stuck onto the silhouette instead of as joint mass.
3. **No sleeves.** The gi has a closed loft over the torso but nothing over the deltoid, so the
   shoulder sphere is the only thing at the shoulder.
4. **No UV chart and no textures.** Every material is a flat Principled BSDF colour; there is no
   albedo/normal/ORM map in the repository for any character.
5. **Rigid per-part skinning.** Each part is 100 % weighted to one bone. It does not tear, but it
   cannot deform smoothly at a joint, which is why the seam spheres exist at all.

Kaze has the same construction (same `loft`/`sphere`/`join_parts` helpers) and shows the same ball
shoulders and jacket stipple in `artifacts/close-kaze-final/kaze-idle.png`. It stays enabled because
its alternative is the primitive prefab, not a better authored body.

**To re-enable an entry:** fix 1–3 in `assets/blender/build_roster_models.py` (give the gi a clean
outward offset from the torso, add a short sleeve over the deltoid, shrink or remove the joint
spheres), rebuild with `npm run build:roster`, then compare with
`bash scripts/run-browser-test.sh scripts/_compare-bodies.mjs artifacts/body-compare`. If the export
now wins, flip `enabled` to `true`; `npm run probe:bodies` will then assert that the GLB is the body
on screen, and `npm run test:animation` will fail until the manifest records the enabled state
consistently.

## 4. What genuinely works on every body, whatever its origin

These are asserted by `npm run probe:bodies` (29 checks) against the live game, on the body that is
actually mounted:

- the body the manifest says is enabled is the body on screen (imported or authored), and a disabled
  entry never leaves a broken or missing body behind;
- a disabled export is still a real file (HTTP 200, > 100 kB) with its rig recorded — the entry is a
  decision, not a dead link;
- the mounted body passes the structural rig gate (upright, drawable meshes, feet on the fighter
  origin, head above pelvis, scale uniform);
- the Iron Spider leg rig (`public/js/anim/spider_legs.js`) is attached to the fighter root, 4 legs
  × 3 joints, posed by the simulation, tips at 1.2–1.4 m spread — on the authored suit;
- a form activates, repaints a real surface (`hair` on Goku, `arc-reactor`/`follower-accent` on Iron
  Man, `appendage` on Iron Spider) and restores the original colour, emissive and scale on expiry;
- the prefab control fighter keeps its 11 joint handles (the shared body path is untouched);
- no character asset request fails and no page error is raised.

The clip-lookup fix in this pass is also covered: `human_fighter.js` now searches clip words in
priority order (it searched all words at once, so `heavy_punch` — which contains `punch` — won the
light-attack lookup, and a light attack played the heavy clip). Kaze's light attack now binds
`jab`, asserted live by sampling the mixer during an attack.

## 5. Blocked assets, stated plainly

The three licensed source packages have never been in this repository and are not used:

| Identity | Expected licensed file | State |
| --- | --- | --- |
| Goku | `public/models/characters/goku/Goku.fbx` + textures | not supplied |
| Iron Man | `public/models/characters/iron-man-mark-v-rig/Iron Man Mark V Rig Materials.gltf` + `.bin` + textures | not supplied |
| Iron Spider | `public/models/characters/iron_spider/iron_spider.glb` (Sketchfab, Kabiidev) | not supplied |

`npm run validate:assets` passes with those entries disabled and reports the files that are missing.
Nothing was downloaded: the repository holds no licence for a third-party character mesh, and an
unlicensed copy is not something this pass will add.

When a licensed package is supplied, the route is already built and tested — drop it in and run
`node scripts/install-character-assets.mjs /path/to/extracted-package` (or
`node scripts/install-character-model.mjs <download> --identity "Iron Spider" --license …`). The
loader, the rig gate, the clip retargeting, the leg rig and the transformation surfaces do not need
to change; only visual acceptance does.

Browser checks actually performed (headless Chromium, software GL): roster selection for all 34
fighters, a live match, a form and an ultimate, Iron Spider's legs, free roam, both HTML entry
points, and the close-up body comparisons above. **Not** performed: a human sitting in front of the
screen. The visual verdict in §3 is based on the screenshots listed there, not on a person's
judgement, so it should be confirmed by eye (see §7).

## 7. Seeing and judging it yourself

```sh
npm ci
npm run dev            # http://localhost:3000
```

Pick **Goku**, **Iron Man (Tony Stark)**, **Iron Spider** and **Kaze** in the roster: `J` light
attack, `K` signature, `I` form, `O` ultimate, `F3` debug overlay.

To reproduce the comparison shots:

```sh
bash scripts/run-browser-test.sh scripts/_compare-bodies.mjs artifacts/body-compare Goku
bash scripts/run-browser-test.sh scripts/_compare-bodies.mjs artifacts/body-compare "Iron Man (Tony Stark)"
```

Each writes `<fighter>--sculpted.png`, `<fighter>--imported.png` and a `--noshadow` variant, so the
same camera judges both bodies. That is the picture to look at before deciding whether the Blender
export is ready to ship.
