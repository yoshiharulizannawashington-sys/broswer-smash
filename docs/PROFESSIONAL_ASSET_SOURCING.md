# Professional asset sourcing and licensing

The visual foundation of a Browser Smash character is a **model somebody else designed**, not
geometry generated by a script. Two procedural approaches were tried and rejected on visual merit:
primitive assembly (Phase 2.1) and implicit-surface/metaball fields (Phase 2.3). Neither produced a
character with a readable face, deliberate silhouette or believable hands, and no further tuning of
those generators is planned.

This document is the sourcing rulebook: what is legally usable, what was verified, and what a new
asset must pass before it is allowed into the game.

## 1. The legal rule that decides everything

A free download is not a licence. Three separate questions have to be answered for every asset:

1. **What licence does the asset page actually state?** (not what a description claims)
2. **Does that licence permit commercial use, modification and redistribution of a derived GLB?**
3. **Does the uploader have the right to license it at all?**

Question 3 is what rules out most "free Goku" models. A fan sculpt of Goku is a derivative work of
the character: the sculptor owns their mesh, but only Toei Animation / Shueisha / Bandai Namco can
license the character itself. A CC BY badge on a fan model conveys nothing from the rights holder,
so it cannot be used in a public or commercial game without a licence from them. This applies even
to a free, non-commercial build: non-commercial status is a factor in a fair-use analysis, not a safe
harbour.

**Consequence for this project:** the roster's copyrighted characters (Goku, Iron Man, Naruto, …)
need either an official licensed model or the owner's written permission. Until then the showcase
bodies stay opt-in and the pipeline is demonstrated with an original, freely licensed character.

### Licence decision table

| Licence | Paid game | Modify (derived GLB) | Redistribute derived GLB | Verdict here |
| --- | --- | --- | --- | --- |
| CC0 1.0 | yes | yes | yes, no conditions | **preferred** |
| CC BY (3.0/4.0) | yes | yes | yes, with credit + licence link + note of changes | **acceptable** |
| CC BY-SA | yes | yes | only if the derived GLB is also BY-SA | avoid |
| CC BY-ND | yes | private only | no | reject |
| CC BY-NC (any) | no | yes | non-commercial only | reject |
| Sketchfab "Editorial" | no | no (technical crops only) | no | reject |
| Sketchfab "Standard" (paid) | generally yes | yes | cannot ship the model as a standalone file | case by case |
| No licence / downloads disabled | no | no | no | reject |

Attribution is a **condition** of CC BY, not a courtesy: without the credit, licence link and a note
that changes were made, the licence does not apply.

## 3. The demonstrated asset, and why it is only a pipeline demonstration

The first real ingestion used **Quaternius' "Animated Base Character"** fetched from Poly Pizza.

- Page: https://poly.pizza/m/cwYvO5UauX
- Licence: **CC BY 3.0** — https://creativecommons.org/licenses/by/3.0/ — *not* the CC0 most
  Quaternius packs use. Attribution is mandatory and is recorded in the manifest entry and in
  `public/models/characters/ingested/quaternius_base.provenance.json`.
- Attribution string carried with the asset: *"Animated Base Character" by Quaternius, via Poly
  Pizza — CC BY 3.0. Bones remapped and clips renamed for Browser Smash; geometry unchanged.*
- It is a **generic studio mannequin** (2 flat materials, no texture maps), not an anime fighter.
  It proves the pipeline; it does not meet the art-direction bar and is not promoted to the roster.

### What this asset demonstrated about the gate

It passes the ingestion gate and fails the geometry gate:

- Ingestion gate: 19/19 canonical bones bound after remapping, feet at 0.000 m, height 1.780 m,
  seven game states exported, watertight (0 open edges), no collapsed bands.
- Geometry gate (`scripts/inspect-character-glb.mjs`): **FAILED** — 6,584 zero-area triangles
  (`Mannequin_2`: 6,580, `Mannequin_1`: 4) out of 13,744. That is a defect in the source export, and
  the gate doing its job is the point: a model that looks fine in a thumbnail is not accepted because
  it downloaded.

## 4. Sourcing procedure for the next character

1. Pick a candidate from §2 (CC0 first). Open its page in a browser and record: creator, page URL,
   licence name **and version**, licence URL, attribution text, whether commercial use is permitted,
   whether modification is permitted, and any redistribution restriction.
2. Download FBX or GLB (GLB preferred; FBX needs conversion before it can be inspected).
3. Put the untouched file in `artifacts/dev/ingest-source/` and write a profile in
   `assets/ingest/<name>.json` (see `docs/CHARACTER_INGESTION.md`).
4. Run `node scripts/ingest-character.mjs --profile assets/ingest/<name>.json`. Fix the profile, not
   the model, when bones or clips do not line up.
5. Run `node scripts/inspect-character-glb.mjs <output>`. A non-zero exit is a stop: the asset is not
   shippable, regardless of how it looks.
6. Review it in a real match with `?showcaseCharacter=<key>` and judge the art direction from front,
   three-quarter and face captures. Only a model that passes all three gates is considered for the
   roster.

## 5. What is still a human decision

The automated gates can prove a rig binds, feet touch the floor, clips exist and geometry is
well-formed. They cannot prove a face reads as a face, that hair looks like hair, or that a
silhouette is deliberate. Those remain a human judgement, made from the renders, and the honest
answer for the currently demonstrated asset is "technically ingested, visually not good enough".

## Phase 26.1 — how the import pipeline works now

Licence metadata is not consulted anywhere in this pipeline. It is copied into the ingestion
profile from a `.source.json` sidecar when one exists, and is reported as `null` otherwise.

### One command

```sh
node scripts/prepare-character.mjs --file <model> --name "Display Name" [--archetype warrior]
     [--source-rig <rigged-reference.glb>] [--bones <correction.json>] [--height 1.8] [--no-autorig]
```

Retrieve a file first with `node scripts/source-character.mjs --file|--url|--search|--sketchfab`.

### Formats

| Format | Path | Verified |
| --- | --- | --- |
| GLB / GLTF | parsed directly, skin and clips read from the glTF JSON | yes |
| FBX | converted to GLB through Blender (`scripts/blender_tools.py convert`) | yes |
| BLEND | converted through Blender; the .blend is opened and exported | implemented |
| OBJ | converted through Blender; OBJ has no skeleton, so it takes the unrigged path | implemented |
| VRM | glTF plus `VRM.humanoid.humanBones`, mapped exactly instead of guessed | implemented, unverified |

### Rig states

1. **Rigged** — skin present and at least 12 of the 19 humanoid slots identified by name.
2. **Unfamiliar names** — skin present but fewer than 12 slots resolve. The pipeline writes
   `assets/ingest/<slug>.bones.template.json` listing every node and every target slot, and stops.
   Fill it in and re-run with `--bones <that file>`. It never guesses a wrong skeleton silently.
3. **Unrigged** — no skin. Blender builds a 19-bone humanoid rig from the mesh bounds and assigns
   validated two-bone distance weights, reporting any bone that received no vertices.

### Animation

Existing clips are claimed for the seven game states (Idle, Walk, Run, Jump, Punch, Kick,
Kamehameha). When a state has no clip, or the model has no clips at all, Blender retargets
world-space bone rotations from a reference rig onto the imported skeleton and bakes one action per
state. Substitutions are recorded in the profile rather than presented as real matches.

### Registration

Registration merges into `assets/ingest/imported-registry.json` and regenerates
`public/js/combat/imported_profiles.js` and `imported_movesets.js` from every entry, so adding a
character never deletes an earlier imported character's moveset. The manifest, the launch roster and
`allRoster` are updated idempotently.

### Review mode, then registration

`prepare-character.mjs` prepares a model into review mode by default: GLB, ingestion profile and
report are produced, and the roster is untouched. Adding a fighter to character select requires the
explicit `--register` flag, so no test import can silently inflate the playable roster.
